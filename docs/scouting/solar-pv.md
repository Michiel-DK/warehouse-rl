# Scouting: does the fleet stall analyser transfer to utility-scale solar PV fleets?

## 1. Fit

The location axis holds for a commercial fleet and not for any public log. A vendor's own model has rows and strings as map objects (Raptor Maps API: `get_geospatial_row_child_geojson`, `get_string_child_geojson`, https://docs.raptormaps.com/reference/get_geospatial_row_child_geojson-1.md, verified@2026-10-19, A), while the public PVDAQ metadata gives only "the site geo-location" (https://data.openei.org/submissions/4568, verified@2026-10-19, A). Faults that recur at places are plausible, since soiling and shading are place-bound, but no source we read shows a string or tracker failing repeatedly at the same place over weeks, so this is unmeasured. Logs with position and state are the weak requirement: the open shading log has per-inverter fault labels and no position (section 2), and the only open tracker stall labels are emulated (DuraMAT, section 2). The next-window requirement holds, since production is logged daily and a day is a natural window. Here "stall" means an underperformance episode per string (sustained output below irradiance-expected output) or a tracker stall (tracker angle not following its command over a run of intervals); our definitions, no URL needed. "Cell" means a string, row, inverter or tracker, and "window" means a day, or a week for soiling. The planner-blind case is a fault the controller cannot see: a soiling patch or a mechanical tracker fault that shows only as a production residual, the same blind spot as a wet cell that is on no map. Partial tracker failures "can go unnoticed" because they only partly reduce output (Anderson et al. 2022, https://research-hub.nlr.gov/en/publications/a-method-for-estimating-time-series-pv-production-loss-from-solar-2/, verified@2026-10-19, abstract only, B-). Our throughput metric is the performance ratio over the window, delivered energy divided by irradiance-expected energy; this is our definition, the pick-rate equivalent.

## 2. Data

Public logs are rare and none pairs string-level position with a fault state. Telemetry standard: the message-level standard PV devices speak is SunSpec Modbus (the VDA 5050 equivalent). The SunSpec information model reference covers inverter and tracker data points (https://sunspec.org/sunspec-information-model-reference-sunspec-alliance/, verified@2026-10-19, B, search excerpt only). **No open log in SunSpec Modbus was found.** IEC 61724-1:2021 is the monitoring standard, and it defines monitoring classes, not a message format (https://knowledge.bsigroup.com/products/photovoltaic-system-performance-monitoring-1, verified@2026-10-19, B, listing only). ## 6. Verdict

We could demo a synthetic PV fleet honestly in two weeks, labelled as synthetic, but not a real one: no open source gives string positions with real stall or soiling events. The first measurement would be the stall detector's time-to-detect and the top-K hotspot precision on a synthetic tracker-and-soiling fleet over seeds 0 to 9, against a persistence baseline, with the emitter writing a telemetry stream that the existing analyser reads. The emitter is the cost: pvlib and pvops give the physics but no fault injection by location, so we would write the layout, soiling and stall injection ourselves. The single blocker is data: the emulated tracker set is the only open stall-labelled log, and its licence, columns and file sizes are unread because the Data Hub redirect target returned 404. A real pilot needs a utility or a vendor demo account, and the walled vendor trees (Raptor Maps' knowledge hub, AlsoEnergy, SmartHelio, Power Factors, SolarEdge, Enphase) are UNTESTED until one is opened.

SCOUT_SCORE: data=1 (open stall labels exist only as emulated, one tracker; no string-level position in any open log); sim=1 (pvlib and pvops have no fault injection by location; an emitter is needed); competition=2 (Raptor Maps has a location map and log upload at rank A, and seven of nine capabilities are UNTESTED on it, so not an open field); fit=2 (location and next-window hold for a commercial fleet, the public-log side is weak).
